# Section 99 — Manual Overrides and Transitional Updates

## 99.1 — Data Source Migration (TXT → JSON)

### Purpose
Migrate from TXT-based metadata ingestion to a JSON-based source of truth to improve data quality, normalization, traceability, and workflow reliability.

### Summary of Change
- `tv_list.txt` and `movies_list.txt` remain user-editable input files.
- A new script (`parse_txt_to_json.py`) converts TXT → JSON.
- JSON files (`shows.json`, `movies.json`) become the canonical source of truth.
- `fetch_tmdb.py` now reads JSON instead of TXT.
- Workflow updated to run parser before TMDB fetch.
- No deletes: entries removed from TXT are marked `active=false`.
- All changes tracked via per-entry `history[]`.

---

## 99.2 — JSON Schema (Authoritative)

Each entry in `data/shows.json` and `data/movies.json` must follow:

```json
{
  "tmdb_id": 12345,
  "official_title": "Official TMDB Title",
  "user_title": "User-entered title",
  "year": 2020,
  "seasons": "*" | [1, 2, 3],
  "active": true,
  "history": [
    {
      "timestamp_utc": "2025-12-20T00:00:00Z",
      "action": "add",
      "changes": {
        "field": "old→new"
      }
    }
  ]
}
```

### Schema Rules
- `tmdb_id` is required; search TMDB if missing.
- `official_title` must always match TMDB canonical naming.
- `user_title` preserves the user’s input.
- `seasons` supports `"*"`, lists, and ranges.
- `active=false` replaces deletion.
- `history[]` must record all adds/updates with UTC timestamps.
- JSON must be written atomically.

---

## 99.3 — Parser Rules (parse_txt_to_json.py)

### Responsibilities
- Read TXT files.
- Split lines by `|`.
- Extract: title, year, TMDB ID, seasons.
- Normalize whitespace and casing.
- Resolve missing TMDB IDs via search.
- Fetch official TMDB titles.
- Convert seasons (`*`, lists, ranges).
- Update JSON atomically:
  - Add new entries.
  - Update changed fields.
  - Mark removed entries as inactive.
- Append history entries for all changes.
- Validate JSON schema before writing.

### Error Handling
- Log malformed TXT lines.
- Log TMDB API failures.
- Log ambiguous search results.
- Log duplicates.
- Append all errors to `data.json["errors"]`.

---

## 99.4 — Workflow Pipeline Update

### New Required Order
1. `parse_txt_to_json.py`  
2. `fetch_tmdb.py`  
3. `fetch_trakt.py`  
4. `sync_trakt.py`  
5. Output: `data/data.json`

### Workflow Requirements
- Fail on schema validation errors.
- Use consistent logging across all scripts.
- All scripts must be deterministic.

---

## 99.5 — TMDB Normalization Rules

### Required Behavior
- Always prefer direct ID fetch (`/tv/{id}`, `/movie/{id}`).
- If ID missing, use TMDB search.
- Normalize titles to TMDB official names.
- Retry API calls 3× with exponential backoff (0.6s base).
- Log all failures.

---

## 99.6 — Traceability and Auditing

### Requirements
- No deletes; inactive flag only.
- All changes recorded in `history[]`.
- Timestamps must be UTC ISO8601.
- JSON must be deterministic and stable across runs.
- Atomic writes required for all JSON outputs.

---

## 99.7 — Interdependency Notes

### Required Chain
- Parser produces JSON.
- TMDB fetch consumes JSON.
- Trakt fetch enriches `data.json`.
- Sync script updates external services.

### Constraints
- No script may re-parse TXT except the parser.
- No script may mutate JSON except the parser.
- No script may bypass schema validation.

---

## 99.8 — Rationale

### Why TXT → JSON Migration
- TXT is human-friendly but structurally unreliable.
- JSON provides:
  - validation  
  - normalization  
  - traceability  
  - atomic updates  
  - consistent schema  
  - reliable downstream processing  

### Benefits
- Eliminates parsing errors.
- Ensures TMDB canonical naming.
- Adds full audit history.
- Improves workflow reliability.
- Enables future automation.
