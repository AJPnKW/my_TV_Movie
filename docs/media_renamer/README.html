Media Cleanup Pipeline

Home-user model: build a plan, then apply safe changes. Safe matches are fixed automatically. Problem files are left alone.

Purpose

This pipeline cleans recorded and downloaded movies and TV episodes under C:\X1_Share\Recordings. It replaces the earlier complex utility workflow with two actions only.

Two actions

ActionWhat happensChanges files?
Build Cleanup PlanScans recordings, validates files, matches against the repo catalog, detects duplicates, and writes reports.No
Apply Cleanup PlanApplies only safe planned moves, renames, duplicate moves, quarantine moves, and empty-folder cleanup.Yes

Final folder structure

The only final media library folders are:

C:\X1_Share\Recordings\TV
C:\X1_Share\Recordings\Movies

The pipeline must not create a final Shows folder. If an accidental Shows folder exists from a previous run, it is scanned, safe content is moved into TV or Movies, and the folder is removed only if empty.

TV destination

C:\X1_Share\Recordings\TV\<Show Name> [<tmdb_id>]\Season 01 - <Season Name>\<Show Name> - S01E01 - <Episode Name>.ext

If the season name is generic or missing, the folder is Season 01.

Movie destination

C:\X1_Share\Recordings\Movies\<Movie Name> (<Year>) [<tmdb_id>]\<Movie Name> (<Year>).ext

Catalog authority

The pipeline matches only against the existing my_TV_Movie repo catalog:

  • data\catalog_index.json
  • data\catalog_detail\*.json

A smaller runtime reference is generated at tools\media_renamer\media_reference.json.

Safe action rules

Safe actionRequirement
TV move/renameConfidence at least 85, destination under TV, known TMDb show ID, known season and episode.
Movie move/renameConfidence at least 85, destination under Movies, known TMDb movie ID.
QuarantineZero-byte, temporary, or ffprobe-broken media file.
Duplicate moveDuplicate identity is deterministic and a better keeper is selected.
Empty folder cleanupOnly after safe moves; no media file is deleted.

Problem files

Problem files are not moved. They are reported when the pipeline cannot prove the correct action. Reasons include low confidence, no catalog match, ambiguous duplicate tie, invalid extensionless file, unlinked sidecar, or unsafe destination.

Specific cleanup behaviours

ConditionBehaviour

moviesContent is migrated to canonical Movies when safely matched.

Sidecars.srt, .ass, .vtt, and .nfo move only when clearly linked.

Commands

Validate

powershell -ExecutionPolicy Bypass -File scripts\validate_media_cleanup_pipeline.ps1

Build Cleanup Plan

powershell -ExecutionPolicy Bypass -File scripts\run_media_cleanup_plan.ps1

Apply Cleanup Plan

powershell -ExecutionPolicy Bypass -File scripts\apply_media_cleanup_plan.ps1

Optional two-button launcher

powershell -ExecutionPolicy Bypass -File scripts\run_media_cleanup_launcher.ps1

Troubleshooting

ProblemFix
Too many problem filesConfirm the titles exist in data\catalog_index.json and details exist under data\catalog_detail.
ffprobe unavailableThe plan still runs, but completeness proof is weaker. Install FFmpeg later if needed.
Apply refuses to runBuild a fresh cleanup plan first.
A folder remainsIt still contains files that were not safe to move. Check problem_files.csv.
