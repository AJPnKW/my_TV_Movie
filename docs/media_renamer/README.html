my_TV_Movie Media Renamer

Purpose

The media renamer is a simple home-user utility for cleaning C:\X1_Share\Recordings. It scans recordings, uses the my_TV_Movie catalog as the only matching authority, prepares a plan, and fixes only safe changes in one batch. It does not ask for per-file approval.

Safe matches will be fixed automatically. Problem files will be left alone.

Home-user workflow

  1. Open the app.
  2. Confirm the recordings folder. The default is C:\X1_Share\Recordings.
  3. Confirm the output root. The default is also C:\X1_Share\Recordings.
  4. Click Scan Recordings.
  5. Read the summary counts: Ready to fix, Already OK, Needs review, Broken/empty, Duplicates, and Skipped support files.
  6. Click Fix Safe Changes. The app moves safe TV episodes, safe movies, broken files, and duplicate extras in one batch.
  7. Use Scan Again after fixing to refresh the summary.

Advanced settings are hidden behind the Advanced settings button. Normal use does not require changing them.

Final folder structure

TV episodeC:\X1_Share\Recordings\TV\<Show Name> [<tmdb_id>]\Season 01 - <Season Name>\<Show Name> - S01E01 - <Episode Name>.ext
TV episode with generic or missing season nameC:\X1_Share\Recordings\TV\<Show Name> [<tmdb_id>]\Season 01\<Show Name> - S01E01 - <Episode Name>.ext
MovieC:\X1_Share\Recordings\Movies\<Movie Name> (<Year>) [<tmdb_id>]\<Movie Name> (<Year>).ext

TV and Movies are the only final media library folders. The tool never creates a third final show library. If an old third folder exists from earlier runs, the scanner includes it, moves valid content into TV or Movies, removes it only when empty, and reports when it cannot be removed.

Catalog and reference data

Matching comes only from this repo:

  • data\catalog_index.json
  • data\catalog_detail\*.json

The app builds tools\media_renamer\media_reference.json for speed. It contains movie TMDb IDs, titles, release years, normalized title tokens, show TMDb IDs, first-air years, seasons, season names, episodes, and episode names.

Matching rules

  • 85% or higher confidence is safe.
  • Below 85% goes to review and is left in place.
  • A TMDb ID in a folder or filename is strong evidence.
  • The parser supports S01E01, s01e01, S2_E1, 5x04, S2026E01, embedded TV provider names such as embed_tv_126027_5_16, and malformed names such as a missing closing parenthesis.
  • Bad padding such as S01E010 is normalized to S01E10.
  • Movie title numbers are preserved, including The Devil Wears Prada 2.
  • A file already inside a show folder is treated as likely belonging to that show, but a stronger filename match can override a wrong folder.
  • Loose files in the recordings root, files in TV\_Unsorted, and files in placeholder folders such as ShowA and ShowB are included.

Duplicates

Duplicates are grouped by destination identity first: TV uses type, TMDb ID, season, and episode; movies use type and TMDb ID. The best copy is kept by preferring readable video, larger size, and an already-normalized file when quality is otherwise equivalent. Same-size files can be hashed when the advanced setting is enabled. Duplicate extras are moved to:

C:\X1_Share\Recordings\_MediaRenamer_Duplicates\<timestamp>\

Duplicates are never silently deleted. The execution log records the kept item and each moved duplicate.

Quarantine

Zero-byte files and broken or incomplete files are not deleted. They are moved only when Fix Safe Changes is clicked:

C:\X1_Share\Recordings\_MediaRenamer_Quarantine\<timestamp>\

A scan is a plan only and never moves files.

Sidecars and support files

.srt, .ass, .vtt, and .nfo files move only when they clearly share the same base name as a matched media file. Unrelated images, documents, scripts, web pages, and other support assets are skipped and reported as support files.

ShowA and ShowB cleanup

ShowA and ShowB are treated as media placeholder folders, not support folders. The scanner includes their files, moves safe matches into final TV or Movies folders, and removes those placeholder folders only if they become empty after safe moves. If anything remains, the folder stays and the execution log explains why.

Reports

The app has buttons for Open latest report, Open reports folder, and Export problem list.

Troubleshooting

ProblemWhat to do
Many files go to reviewCheck whether the show or movie exists in data\catalog_index.json and data\catalog_detail. The renamer does not use internet lookups.
Extensionless file stays in reviewEnable the advanced ffprobe check if ffprobe is installed. If it still cannot prove a video stream, the file is left alone.
Destination already existsThe tool avoids overwriting by adding a numbered suffix or by classifying duplicate extras. Inspect the duplicate report before deleting anything manually.
Old placeholder folder remainsThe folder was not empty after safe fixes. Open the latest execution log to see which files blocked cleanup.
Reports are missingRun validation. The validator checks syntax, rules, reference building, parser coverage, report expectations, PySide6 usage, and TV/Movies output rules.
