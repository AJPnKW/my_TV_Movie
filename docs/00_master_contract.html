3. UI Contract

3.1 Header and Navigation

  • Header contains Boys logo, primary icon navigation, and Ready/version status.
  • Primary nav icons are standalone Unicode/web icons, not boxed buttons.
  • Icons must be large enough to scan visually and must not overlap at desktop, partial desktop, tablet, or phone widths.
  • Ready/version block must not collide with navigation.
  • Boys logo must preserve aspect ratio and must not stretch into a banner.
  • Header is sticky and compact.

3.2 Media Cards

[ image ]
[ title + metadata ]
[ action row ]
  • Action row is always below media/text, never over image.
  • No availability badge overlays on poster/still artwork.
  • Show cards use one renderer everywhere.
  • Movie cards use one renderer everywhere.
  • Episode cards use one renderer family everywhere.

3.3 Action Icon Strip

Required order:

IconMeaning
🍿Watch source / availability popup
⌚watched_status toggle
🎫watch_list toggle
💕favourite toggle
76%compact rating percentage
  • Icon boxes must be rounded-square, not circles or pills.
  • No border-radius:999px for action buttons.
  • No action-row mini-frame.
  • Forbidden active icons: ▶ 🎬 📏 💛 ⭐.

3.4 Filter Rails

  • Library Filters stay on the left on desktop/tablet and stack only on true mobile.
  • Hide/show control sits on the rail edge, not inside the filter content.
  • Remove unwanted text: “Browse” and “Shared cards, shared actions, one left filter rail.”

3.5 Sticky Sections

  • Dashboard sections have sticky headers: current week, watchlist, upcoming, recommendations.
  • Sticky headers must replace naturally as the next section scrolls into view.

4. Watch State and Manage Watch State View

4.1 State Types

StateMeaningUI Control
watch_listUser intends to watch later.Two-state switch on/off.
favouriteUser likes item / recommendation signal.Two-state switch on/off.
watched_statusUnwatched, partially watched, watched.Three-state segmented switch if supported by data/Trakt; otherwise local tri-state and Trakt-compatible mapping.

4.2 Manage View Layout

  • Standalone page: web/manage_watch_state.html.
  • Not embedded in Config.
  • Lean matrix/table body with tree structure: show → season → episode; movies as single rows.
  • Column headers identify toggles; row controls are compact switches, not large named buttons.
  • Filters: type, watch_list, watched_status, favourite, Trakt mismatch, missing ID, queued update, unreleased blocked.
  • Bulk actions are allowed only where safe and must respect release-state constraints.

4.3 State Key Format

<state_type>:movie:<tmdb_id>
<state_type>:show:<tmdb_id>
<state_type>:season:<show_id>:<season_number>
<state_type>:episode:<show_id>:<season_number>:<episode_number>

4.4 Release-State Constraints

  • Unreleased movie cannot be marked watched.
  • Unreleased episode cannot be marked watched.
  • Season cannot be fully watched if eligible released episodes are incomplete or unreleased episodes are included in the rollup incorrectly.
  • Show rollup is derived from seasons/episodes, not manually guessed.

5. Trakt Integration Contract

Trakt integration is local-first, queue-based, and explicit. No UI action may block on a network call.

Trakt pull → normalize → compare → local queue → push → pull confirmation → reconcile → report
WorkflowRequired Output
PullTrakt watched/history, watchlist, ratings/favourites-equivalent if available.
CompareLocal vs Trakt mismatch list.
PushQueued local changes sent to Trakt.
ReconcilePull after push and update local state.
Auth recoveryClear error report and next action; no silent failure.
  • Primary match key: tmdb_id.
  • Never title-only matching.
  • Existing scripts such as scripts/trakt_http.py, scripts/fetch_trakt.py, scripts/sync_trakt.py, scripts/trakt_device_auth.py, scripts/trakt_sync_watch_state.py, scripts/trakt_push_watch_queue.py, and scripts/run_pipeline_tmdb_trakt.py must be audited and either integrated, archived, or documented as inactive.

8. Standalone Watchlist / Simple Trailer-Friendly View

Historical Section 4.9 describes web/watchlist.html as a standalone non-SPA page. This concept remains useful, but the old spec is historical until rebuilt under this contract.

Retained Concept

  • Simple standalone listing, fast to load on slow trailer internet.
  • Uses same data source, preferably optimized runtime index where possible; data/data.json acceptable if explicitly validated for performance.
  • Can use collapsed show rows and expandable show → season → episode tree.
  • No SPA router dependency.
  • No duplicate watch-state ownership; uses shared state keys if interactive.

Decision

watch_me.html and watchlist.html must be rationalized. If both exist, they need distinct purposes or one becomes a compatibility redirect.
