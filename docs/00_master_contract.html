3. UI, Navigation, Cards, and Media Sizes

  • Full app header/top navigation is sticky on every runtime page, not just this documentation page.
  • Major section headers are sticky and hand off naturally to the next section header.
  • Primary nav uses standalone icons, not boxed buttons.
  • Boys logo preserves aspect ratio and cannot stretch into a banner.
  • Card action row is below media/text and never overlays image or metadata.
  • Show/movie posters in grids, Shows, Movies, and Dashboard Recommendations use poster Half 171x257.
  • Episode stills use Narrow Still Half 240x135; source/optimized still target remains 320x180 before crop.
  • Calendar episode cards use episode stills only, never show/movie posters.

4.1 Cross-view Consistency

  • The same media item must show the same watch_list, favourite, and watched_status in Dashboard, Shows, Movies, Calendar, Discover, Watch Me, and Manage Watch State.
  • State cannot be view-local. One canonical state key must drive all views.
  • When a user clicks an action icon in one view, every matching card/row in every active view must render the same state after refresh/rerender.
  • Action visual state must be both readable and functional: if it lights up, the underlying state must exist; if state changes, the icon must change.
  • Validation must click ⌚/🎫/💕 on a card, confirm visual state changes, confirm queue/local state changes, then open Manage Watch State and confirm the same media row changed.

5. Episode Carousel Contract

Episode rows are not acceptable as plain horizontal overflow rows. They must be true carousels with controls, focus management, and retained context.

RequirementContract
ContainerEach show/season episode strip is a named carousel region with accessible label containing show and season context.
NavigationVisible previous/next controls; keyboard left/right; Android TV D-pad left/right; optional page dots/count.
Context retentionShow title and season title/header remain visible while moving through carousel items. Horizontal scrolling must not make the user lose the show/season context.
Card layoutEpisode cards use Narrow Still Half 240x135 and consistent episode metadata.
FocusFocus stays inside the carousel while navigating cards and controls; D-pad up/down moves predictably to previous/next section.
Scroll behaviorCarousel can use scroll-snap but must also expose real controls. A plain overflowing row without carousel controls fails validation.

7. Trakt Sync Contract

device auth → pull → normalize → compare → local queue → push → confirmation pull → reconcile → report
  • Trakt two-way sync is required and not optional.
  • UI writes are local-first and queue-backed. Live network response is not required for immediate UI change.
  • Primary match key is ID-based: Trakt, TMDB, IMDB, TVDB, slug where available. Title-only writes are forbidden.
  • Required pull endpoints: GET /sync/watchlist, GET /sync/history/movies, GET /sync/history/episodes.
  • Required push endpoints: POST /sync/watchlist, POST /sync/watchlist/remove, POST /sync/history, POST /sync/history/remove.
  • partial watched_status is local-only unless a specific Trakt playback/progress mapping is intentionally implemented.
  • favourite is local-only unless explicitly mapped to Trakt ratings or another Trakt-supported construct. If local-only, the UI must say local_only.
  • The same state value must display consistently across all pages.

8. CI/CD and Workflow Contract

WorkflowRequired behavior
.github/workflows/validate.ymlRuns syntax, availability validation, asset validation, runtime catalog integrity, JS checks, rendered/browser QA, and Trakt dry-run. Must use Node 24 action majors and Python 3.12.
.github/workflows/build-data.ymlRuns full data pipeline, validates JSON, uploads diagnostics on success/failure, commits generated artifacts, then dispatches Pages after artifact commits.
.github/workflows/pages.ymlDeploys GitHub Pages using workflow deployment so bot-generated data commits publish.
  • Every script referenced by workflows must exist in repo and be syntax validated. Missing validator scripts fail the contract.
  • Workflow steps must not reference retired files such as removed watch_me runtime files.
  • Availability validation scripts must be explicit and present: validate_availability_overlay.py, enrich_data_with_availability.py, qa_availability_status.py, qa_availability_phase2.py, validate_runtime_assets.py, validate_runtime_catalog_integrity.py, plus any replacement explicitly listed here.
  • Asset self-heal must run before runtime asset validation where missing assets can be fetched safely.
  • Node 20 warnings are not accepted as harmless drift; workflow actions must be updated to supported Node 24 action majors.
  • Failure logs and reports must be uploaded as artifacts even when the main pipeline fails.
  • Credential existence is not enough. Workflows must pass all required secrets into the exact steps that use them.

9. Validation Acceptance Tests

  • Click ⌚/🎫/💕 on Dashboard card → visual state changes → queue/local state changes → Manage Watch State row matches.
  • Repeat same click test on Shows and Movies card views.
  • Verify same media item has same state across Dashboard, Shows, Movies, Calendar, Discover, Watch Me, Manage Watch State.
  • Episode carousel test: show/season header remains visible, next/previous controls work, keyboard and D-pad navigation work, plain overflowing row fails.
  • Manage Watch State test: search works, type filter works, rows-per-page changes, first/previous/next/last work, column-header sorting works, inline state edits persist and queue.
  • Trakt dry-run test: queued records generate endpoint-specific payloads or explicit local_only/missing_id/validation_issue status.
  • CI test: validate, build-data, and pages workflows pass; workflow diagnostics artifacts exist when failure occurs.
