3. UI, Navigation, Cards, and Media Sizes

  • Full app header/top navigation is sticky on every runtime page.
  • Major section headers are sticky and hand off naturally to the next section header.
  • Primary nav icons are standalone Unicode/web icons, not boxed buttons.
  • Boys logo must preserve aspect ratio and cannot stretch into a banner.
  • Card action row is below media/text and never overlays image or metadata.
  • Show/movie posters in grids, Shows, Movies, and Dashboard Recommendations use poster Half 171x257.
  • Episode stills use narrow still Half 240x135; episode source still 320x180 is the source/optimized still target before crop.
  • Calendar episode cards use episode stills only, never show/movie posters.
  • Header cell left/right bounds must align exactly with matching calendar day columns.

4.1 Cross-view Consistency

  • The same media item must show the same watch_list, favourite, and watched_status in Dashboard, Shows, Movies, Calendar, Discover, Watch Me, and Manage Watch State.
  • State cannot be view-local. One canonical state key must drive all views.
  • When a user clicks an action icon in one view, every matching card/row in every active view must render the same state after refresh/rerender.
  • Action visual state must be both readable and functional: if it lights up, the underlying state must exist; if state changes, the icon must change.
  • Validation must click ⌚/🎫/💕 on a Dashboard card and Calendar card, confirm visual state changes, confirm queue/local state changes, then open Manage Watch State and confirm the same media row changed.

5. Episode Carousel Contract

Episode rows are not acceptable as plain horizontal overflow rows. A carousel means an explicit controlled widget, not a CSS row with overflow.

Required elementAcceptance rule
Carousel shellRendered DOM has one parent .episode-carousel or equivalent carousel role/contract marker.
Header/contextShow title and season title remain visible while moving through episodes.
ViewportDedicated carousel viewport clips the track; it is not just the page row overflowing horizontally.
TrackDedicated track contains episode cards and uses scroll-snap or transform/page movement.
ControlsVisible previous and next buttons exist, are focusable, and change the visible episode card group.
CardsEpisode cards use Narrow Still Half 240x135, episode title, SxxExx, runtime/date, and action row.
Keyboard/D-padLeft/right moves inside the carousel; up/down exits predictably to surrounding sections.
ProofRendered QA must click next/previous and verify scroll/transform position changes and context remains visible.

Fail condition: a row of episode data or plain horizontal scroll without carousel controls is not a carousel.

7. Trakt Sync Contract

device auth → pull → normalize → compare → local queue → push → confirmation pull → reconcile → report
  • Trakt two-way sync is required and not optional.
  • UI writes are local-first and queue-backed. Live network response is not required for immediate UI change.
  • Local queue file is data/watch_state_queue.json.
  • Primary match key is ID-based: Trakt, TMDB, IMDB, TVDB, slug where available. Title-only writes are forbidden.
  • Required pull endpoints: GET /sync/watchlist, GET /sync/history/movies, GET /sync/history/episodes.
  • Required push endpoints: POST /sync/watchlist, POST /sync/watchlist/remove, POST /sync/history, POST /sync/history/remove.
  • partial watched_status is local-only unless a specific Trakt playback/progress mapping is intentionally implemented.
  • favourite is local-only unless explicitly mapped to Trakt ratings or another Trakt-supported construct. If local-only, the UI must say local_only.
  • The same state value must display consistently across all pages.

8. Watch Provider Link Health Contract

Provider links are treated as external health-checked targets. The app must not keep broken, unsafe, or redirect-abusive providers active.

StatusMeaningRuntime behavior
activeDomain opens over modern HTTPS, does not redirect to unrelated advertising/security-risk domains, and creates a usable provider page.May show in popup.
degradedIntermittent, slow, or partial failures.May show behind warning or lower priority.
blockedDNS failure, unsupported SSL/TLS, empty tab/no URL, known spam redirect, browser security failure, or user-reported unsafe behavior.Must not appear as normal provider option.
archivedPreviously used provider retained only for audit/history.Not active.
  • Provider QA must record domain, generated URL pattern, media type, TMDB ID, season/episode, status code/error class, redirect final domain if safe to capture, test timestamp, and disposition.
  • Provider QA must classify browser messages like ERR_SSL_VERSION_OR_CIPHER_MISMATCH as provider-side TLS/SSL failure unless evidence proves local browser issue.
  • Provider links that open a blank tab with no URL or no target must be classified as broken generation logic.
  • Provider links that redirect to unrelated advertising or unsafe domains must be blocked/archived.
  • The app must not auto-discover or add unknown replacement providers without explicit review and health classification.

9. CI/CD and Workflow Contract

WorkflowRequired behavior
.github/workflows/validate.ymlRuns syntax, availability validation, asset validation, runtime catalog integrity, JS checks, rendered/browser QA, provider health QA, and Trakt dry-run. Must use Node 24 action majors and Python 3.12.
.github/workflows/build-data.ymlRuns full data pipeline, validates JSON, uploads diagnostics on success/failure, commits generated artifacts, then dispatches Pages after artifact commits.

  • Every script referenced by workflows must exist in repo and be syntax validated.
  • Workflow steps must not reference retired files.
  • Node 20 warnings are not accepted as harmless drift; workflow actions must be updated to supported Node 24 action majors.
  • Failure logs and reports must be uploaded as artifacts even when the main pipeline fails.
  • Credential existence is not enough. Workflows must pass all required secrets into the exact steps that use them.

10. Validation Acceptance Tests

  • Click ⌚/🎫/💕 on Dashboard card and Calendar card → visual state changes → queue/local state changes → Manage Watch State row matches.
  • Verify same media item has same state across Dashboard, Shows, Movies, Calendar, Discover, Watch Me, Manage Watch State.
  • Episode carousel test: show/season header remains visible, previous/next controls work, keyboard and D-pad navigation work, scroll/transform position changes, plain overflowing row fails.
  • D-pad/Android TV validation must prove focus order, popup trapping, and Back/Escape close behavior.
  • Manage Watch State test: search works, type filter works, rows-per-page changes, first/previous/next/last work, column-header sorting works, inline state edits persist and queue.
  • Provider health test: broken TLS, DNS failure, blank URL generation, and unsafe redirect domains are blocked or archived and not shown as normal active options.
  • Trakt dry-run test: queued records generate endpoint-specific payloads or explicit local_only/missing_id/validation_issue status.
  • CI test: validate, build-data, and pages workflows pass; workflow diagnostics artifacts exist when failure occurs.

11. Control Thread Drift-Prevention Rules

Failure modeRequired correction
Assistant accepts a label such as “carousel” without rendered proof.Reject as unproven. Require visible shell, viewport, track, prev/next controls, movement, retained context, and D-pad/keyboard QA.
Detailed user example becomes a vague requirement.Preserve the example verbatim or convert it into a measurable acceptance test.
Codex reports success but user screenshot contradicts it.User screenshot wins. Reclassify as failed validation and fix root cause.
Feature works on one page but not another.Classify as cross-view state or renderer ownership drift. Fix shared owner, not one page.
Provider URL works/fails inconsistently.Classify by health state and generated URL pattern; do not keep unsafe or broken providers active.

12. Accountability

  • No deferrals for items above.
  • Do not report success unless behavior is proven in rendered/browser QA or deterministic script output.
  • Do not generalize user feedback into broad labels; preserve operational details.
  • If behavior is not implemented, classify as failed validation or blocked by a concrete external dependency.
