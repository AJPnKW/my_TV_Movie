3. UI Contract

3.1 Header and Navigation

  • The full app header/top navigation is sticky at the top of the viewport on every page.
  • Sticky behavior must be attached to the actual live app header, not only the documentation header.
  • No ancestor wrapper may block sticky behavior through overflow:hidden, overflow:auto, overflow:clip, transform, contain, or incorrect scroll container assignment.
  • Primary nav icons are standalone Unicode/web icons, not boxed buttons.
  • Ready/version block must not collide with navigation.
  • Boys logo must preserve aspect ratio and must not stretch into a banner.

3.2 Section Sticky Headers

  • Every major view section uses a sticky section header.
  • A section header sticks only while its section is active; when the next section enters, the next section header becomes the sticky header.
  • Dashboard required sticky sections: Current/Recent, Upcoming Schedule, Watchlist, Recommendations.
  • Shows/Movies/Discover/Manage Watch State required sticky headers: filter/context header and result-set header.
  • Sticky section headers must offset below the sticky app header and must not cover cards.

3.3 Media Cards and Sizing

[ image ]
[ title + metadata ]

  • Action row is always below media/text, never over image.
  • No availability badge overlays on artwork.
  • Show cards use one renderer everywhere.
  • Movie cards use one renderer everywhere.
  • Episode cards use one renderer family everywhere.
  • Calendar episode cards must use episode still images, not poster images.
  • Show/movie poster displayed in grids, Shows view, Movies view, and Dashboard recommendations uses the Half poster size: 171x257.
  • Episode stills use Narrow Still Half: 240x135 for display where the narrow card design is required. Source may be 320x180 and cropped left/right to preserve focus without distortion.
  • Recommendation cards must not become large feature/hero cards unless explicitly documented as a separate hero layout. Current dashboard recommendations are compact cards.

  • No border-radius:999px for action buttons.
  • No action-row mini-frame.

3.5 Provider / Watch Popup Media Detail

  • Watch-source popup must include a shared media-detail header before streaming/provider buttons.
  • Episode popup detail block must include: show title, episode title, season/episode code, runtime, release date, and overview when available.
  • Example content pattern: Abbott Elementary / Team Building / S05E01 • 22 min / Oct 1, 2025 / overview text.
  • Movie popup detail block must include: movie title, runtime, release date/year, and overview when available.
  • The detail block should reuse the same data formatter used by episode/movie carousel/card metadata so wording stays consistent.
  • Streaming/provider buttons must use tightened spacing and compact grouping; popup should not waste vertical space.

4. Watch State and Manage Watch State View

  • Standalone page: web/manage_watch_state.html.
  • Lean matrix/table body with tree structure: show → season → episode; movies as single rows.
  • Initial render target: no more than 50 visible rows unless validated otherwise.
  • Column headers identify toggles; row controls are compact switches, not big named buttons.
  • watch_list is binary with values off and on.
  • favourite is binary with values off and on.
  • watched_status is tri-state with values unwatched, partial, and watched.
  • Clicking the ⌚ action cycles watched_status: unwatched → partial → watched → unwatched.
  • Clicking 🎫 toggles watch_list; clicking 💕 toggles favourite.
  • Each local state change stores: item key, item type, tmdb_id, trakt_id if available, show_id, season_number, episode_number, state_type, previous_value, new_value, changed_at, sync_status, validation_status, and sync_error when present.
  • Each queue record in data/watch_state_queue.json stores exactly: id, media_type, state_type, previous_value, new_value, ids with trakt/tmdb/imdb/tvdb, show with season/episode, changed_at, sync_status, validation_status, and error.
  • Required sync_status values are exactly: local_only, queued, synced, mismatch, missing_id, validation_issue, auth_required, failed.
  • Action clicks update UI immediately, update local state, create/update a local queue event, update the Manage Watch State row, and set sync_status to queued unless blocked by validation.
  • Partial watched_status is local-only for API push but still persists locally and remains visible in UI and queue/report state.
  • Unreleased movie/episode cannot be marked watched.
  • Title-only matching is forbidden. Missing TMDB or Trakt IDs must compute missing_id or validation_issue; they must not be hidden behind static text.
  • Manage Watch State columns Trakt status, Mismatch, Queued, and Validation issue are computed from local state, Trakt state, queue state, and validation rules. They are not placeholder labels.

5. Trakt Integration Contract

device auth → pull → normalize → compare → local queue → push → confirmation pull → reconcile → report
  • Local-first, queue-based, and explicit.
  • Base API URL: https://api.trakt.tv.
  • Required request headers: Content-Type: application/json, trakt-api-version: 2, trakt-api-key: CLIENT_ID, and Authorization: Bearer TOKEN for authenticated calls.
  • Required pull endpoints: GET /sync/watchlist, GET /sync/history/movies, and GET /sync/history/episodes.
  • Required push endpoints: POST /sync/watchlist, POST /sync/watchlist/remove, POST /sync/history, and POST /sync/history/remove.
  • Watchlist add payload example: {"movies":[{"ids":{"tmdb":123}}],"shows":[{"ids":{"tmdb":456}}]}.
  • History add payload example: {"episodes":[{"ids":{"tmdb":111},"watched_at":"ISO"}]}.
  • Primary match key: tmdb_id. Payload generation must use IDs only.
  • Never title-only matching.
  • If credentials/token are missing, local UI and local queue still work; status shows auth_required; validation passes the local workflow and reports the external credential blocker only.
  • A dry-run payload must be available from queued records and must prove whether each queued event maps to an add/remove watchlist/history payload or a local-only validation result.
  • Existing workflow scripts are part of the scaffold/audit set: scripts/trakt_http.py, scripts/fetch_trakt.py, scripts/sync_trakt.py, scripts/trakt_device_auth.py, scripts/trakt_sync_watch_state.py, scripts/trakt_push_watch_queue.py, and scripts/run_pipeline_tmdb_trakt.py.

8. Calendar Display Contract

  • Calendar grid remains seven columns on desktop/tablet and preserves horizontal scroll where needed.
  • Calendar must not collapse to stacked cards except on true mobile breakpoints explicitly validated for usability.
  • Calendar must use one shared column definition for weekday/date header cells, day columns, and episode card columns.
  • Header cell left/right bounds must align exactly with the matching day column left/right bounds for the first calendar row.
  • Calendar must use one sticky week/day header row that includes weekday and date together.
  • Do not render a redundant date number row inside each day when the sticky week header already shows day/date.
  • First calendar row must not have offset, padding, border, or gap mismatch against the sticky weekday/date header row.
  • Saturday and Sunday columns use a lighter grey/differentiated background to visually separate weekends from weekdays.
  • Calendar cards for episodes use episode still images, never show/movie posters.
  • Dashboard and Calendar share +X more / expand behavior.

9. Validation and QA Contract

powershell -ExecutionPolicy Bypass -File scripts/validate_runtime.ps1
  • Sticky app header validation: scroll and verify top nav remains visible.
  • Sticky section header validation: scroll through each section and verify active section header replacement.
  • Calendar validation: one sticky weekday/date header row; no redundant per-cell date row; weekend shading present; episode cards use stills; header cell left/right bounds match matching day column bounds.
  • Popup validation: episode/movie provider popup includes media-detail block and compact provider buttons.
  • Popup acceptance example is mandatory: Abbott Elementary, Team Building, S05E01 • 22 min, Oct 1, 2025, and The teachers prepare for the upcoming school year with new faces and big changes on the horizon.
  • Card size validation: poster cards render near 171x257; narrow still cards render near 240x135; episode source still target remains 320x180.
  • Watch-state validation: watched_status includes partial; action clicks create local queue events; Manage Watch State status cells are computed; title-only matching is absent.
  • Trakt validation: click-generated queue records must include IDs; missing IDs must compute missing_id or validation_issue; queue records must generate dry-run payloads for required endpoints; static placeholder status text is a failure.
  • D-pad/Android TV validation: focus order works across nav, cards, popup, and Manage Watch State rows; popup traps focus; background does not receive arrow navigation while popup is open; Escape/Back closes the top popup; scrollbars or clear scroll affordance is present where content overflows.
  • Dashboard duplicate detection: same media key may not render twice within same day/section unless explicitly allowed.
  • Performance regression gate: optimization passes must not increase index/calendar initial load time without documented reason.
