TMDB-ID Streaming Embed Providers

Clean URL patterns, provider catalog, and integration notes for TV shows and movies using TMDB IDs.

One deterministic contract for all providers: tv/{tmdb_id}/{season}/{episode} and movie/{tmdb_id} (or equivalent).

1. Overview

This document captures a structured view of streaming embed providers that accept TMDB IDs for TV shows and movies. The goal is to give you:

  • One clean reference for URL formats across providers.
  • Deterministic patterns you can generate from TMDB IDs, seasons, and episodes.
  • Implementation-ready artifacts: JSON manifest, regex patterns, and health-check strategy.
Core assumptions
  • Input: TMDB ID, and for TV: season + episode.
  • Output: Provider-specific embed URL for TV or movie.
  • Usage: Typically loaded in an iframe or player wrapper.
What this page gives you
  • Provider matrix (TV + movie URL formats).
  • JSON manifest for programmatic use.
  • Regex contracts for validation and parsing.
  • Health-check and fallback strategy.

// Conceptual contract (pseudo-code)

movie_url(provider, tmdb_id)                 -> string

5. Regex patterns for validation and parsing

These regex patterns are designed for:

  • Validation – confirm a URL matches a known provider format.
  • Parsing – extract tmdb_id, season, and episode.

5.1. Generic path-based providers

For providers that use the simple path pattern /tv/{tmdb_id}/{season}/{episode} and /movie/{tmdb_id}: 

// TV (path-based)
^https:\/\/(?<host>[^\/]+)\/(?:embed\/)?tv\/(?<tmdb_id>\d+)\/(?<season>\d+)\/(?<episode>\d+)\/?$

// Movie (path-based)
^https:\/\/(?<host>[^\/]+)\/(?:embed\/)?movie\/(?<tmdb_id>\d+)\/?$

This will match hosts like: vidsrc.net, vidsrc.to, player.videasy.net, superembed.stream, multiembed.mov, smashystream.com, flixhq.to, sflix.to, vidsx.to, etc.

5.2. 2Embed (query-string style)

// 2Embed (org) TV
^https:\/\/www\.2embed\.org\/embed\/tv\?tmdb=(?<tmdb_id>\d+)&season=(?<season>\d+)&episode=(?<episode>\d+)$

// 2Embed (org) Movie
^https:\/\/www\.2embed\.org\/embed\/movie\?tmdb=(?<tmdb_id>\d+)$

5.3. 2Embed (cc) mixed style

// 2Embed (cc) TV
^https:\/\/www\.2embed\.cc\/embedtv\/(?<tmdb_id>\d+)&s=(?<season>\d+)&e=(?<episode>\d+)$

// 2Embed (cc) Movie
^https:\/\/www\.2embed\.cc\/embed\/(?<tmdb_id>\d+)$

5.4. TheNext.video with token

// TheNext.video TV
^https:\/\/thenext\.video\/(?<token>[^\/]+)\/tv\/(?<tmdb_id>\d+)\/(?<season>\d+)\/(?<episode>\d+)\/?$

/* TheNext.video Movie */
^https:\/\/thenext\.video\/(?<token>[^\/]+)\/movie\/(?<tmdb_id>\d+)\/?$

6. Provider health checks and status

Providers change domains, go offline, or alter patterns. Instead of guessing, you can run lightweight health checks and maintain a small status cache.

Health check strategy
  1. Pick a known-good TMDB ID for a popular movie and TV episode.
  2. Generate URLs for each provider using the manifest.
  3. Perform HEAD or lightweight GET (no auto-follow in your app, just status).
  4. Mark provider as healthy if status is 200/302 and not an obvious error page.
  5. Cache results for a few hours to avoid hammering providers.
Example health status model
{
  "vidsrc_net":   { "status": "ok",    "last_checked": "2026-04-04T22:00:00Z" },
  "videasy":      { "status": "ok",    "last_checked": "2026-04-04T22:00:00Z" },
  "2embed_cc":    { "status": "warn",  "last_checked": "2026-04-04T22:00:00Z" },
  "thenext":      { "status": "token", "last_checked": "2026-04-04T22:00:00Z" }
}

In your UI, you can surface this as a simple badge:

Healthy Degraded / intermittent Offline / disabled

7. Integration patterns and enhancements

This section focuses on how to wire everything together in a deterministic, low-surprise way.

7.1. URL factory (pseudo-code)

function buildTvUrl(providerKey, tmdbId, season, episode) {
  const p = manifest.providers.find(x => x.key === providerKey);
  if (!p) throw new Error("Unknown provider: " + providerKey);

  return p.tv_template
    .replace("{tmdb_id}", String(tmdbId))
    .replace("{season}", String(season))
    .replace("{episode}", String(episode));
}

function buildMovieUrl(providerKey, tmdbId) {
  const p = manifest.providers.find(x => x.key === providerKey);
  if (!p) throw new Error("Unknown provider: " + providerKey);

  return p.movie_template
    .replace("{tmdb_id}", String(tmdbId));
}

7.2. Fallback chain

Define a deterministic fallback order so the app never “guesses” which provider to use: 

const FALLBACK_ORDER = [
  "vidsrc_net",
  "videasy",
  "superembed",
  "multiembed",
  "smashystream",
  "flixhq",
  "sflix",
  "2embed_cc",
  "2embed_org"
];

At runtime:

  1. Filter FALLBACK_ORDER by providers currently marked as status === "ok".
  2. Pick the first one and generate the URL.
  3. If the iframe fails to load, optionally offer a “Try another source” button that moves to the next provider.

7.3. Logging and observability

  • Log provider usage (which provider was chosen for each request).
  • Log failures (HTTP errors, iframe load errors, timeouts).
  • Periodically export stats to see which providers are most reliable.

Appendix A – Provider-specific notes

A.1. VidSrc family

  • Members: vidsrc.net, vidsrc.to, vidsrc.cc, vidsx.to.
  • Pattern: consistent path-based /embed/tv/ and /embed/movie/.
  • Usage: good default choice in a fallback chain.

A.2. Videasy

  • Pattern: player.videasy.net/tv/... and /movie/....
  • Role: clean alternative to VidSrc with similar semantics.

A.3. 2Embed

  • Domains: 2embed.cc and 2embed.org.
  • Pattern: uses query-string parameters for TMDB ID, season, and episode.
  • Note: treat these as slightly different from path-based providers in your URL factory.

A.4. TheNext.video

  • Pattern: requires a {token} segment in the path.
  • Usage: only include in your manifest if you have a stable way to obtain the token.

A.5. SuperEmbed, MultiEmbed, SmashyStream, FlixHQ, SFlix

  • Pattern: all follow the same path-based contract.
  • Role: excellent for fallback diversity; they share the same conceptual URL shape.

Appendix B – Future extensions and enhancements

B.1. Versioned manifest

To avoid drift, you can version the manifest: 

{
  "version": 1,
  "updated_at": "2026-04-04T22:00:00Z",
  "providers": [ /* ... as above ... */ ]
}

B.2. Per-provider feature flags

You can extend each provider entry with feature flags: 

{
  "key": "vidsrc_net",
  "name": "VidSrc (net)",
  "tv_template": "https://vidsrc.net/embed/tv/{tmdb_id}/{season}/{episode}",
  "movie_template": "https://vidsrc.net/embed/movie/{tmdb_id}",
  "style": "path",
  "features": {
    "supports_subtitles": true,
    "supports_dubbed": true,
    "supports_poster_proxy": false
  }
}

B.3. Client-side selection hints

  • Latency-aware selection: prefer providers with historically lower load times.
  • Region hints: some providers may work better in specific regions; you can store that in the manifest.
  • User preferences: allow users to pin a preferred provider, falling back only when it fails.
