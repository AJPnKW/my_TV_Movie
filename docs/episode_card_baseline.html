Added: Shared renderer markers, density contract, image resolver contract, anti-drift validation.

Updated: Calendar, Dashboard Current/Recent, and show-detail episode carousel must route through web/js/app_runtime.js::buildSharedEpisodeCard.

Origin: Calendar and Dashboard episode cards visibly diverged in layout, spacing, metadata placement, and still-image treatment.

Validation: scripts/validate_streaming_episode_cards.py, scripts/validate_runtime.ps1, and scripts/qa_browser_layout_check.mjs.

Renderer Contract

Every episode card surface must call buildSharedEpisodeCard. Views may pass data, context, and density, but must not define independent episode-card markup or call the compact renderer directly.

Rendered episode cards carry data-episode-card-renderer="buildSharedEpisodeCard", data-episode-card-density, and data-image-resolver="episodeStillImageForCard".

Densities

DensityUseRule
standardDashboard Current/Recent and show-detail episode carousel.Uses the canonical episode markup with standard card sizing.
compactCalendar grid/list density.Uses the same markup and only adjusts sizing through density classes.

Image Fallback Order

episodeStillImageForCard resolves images in this order: episode still local path, episode still TMDB path, episode still/thumb aliases, show backdrop local/TMDB path, show poster local/TMDB path, deterministic no-still placeholder.

GitHub Pages paths must remain compatible with https://ajpnkw.github.io/my_TV_Movie/web/index.html. Runtime must not reference deprecated image folders.

Required Metadata

Episode cards must render title, episode title, season/episode label, runtime where available, progress/rating indicator where available, TMDB ID in metadata, availability/watch/source icons, and watched/favourite/watchlist state indicators.

Covered Surfaces

The baseline covers Calendar grid/list episode items, Dashboard Current/Recent episode items, show-detail episode carousel cards, and any future episode-card surface that displays the same media-card contract.

Anti-Drift Validation

Validation fails if Calendar or Dashboard define independent episode-card markup, call the compact renderer directly, omit shared renderer markers, omit the shared image resolver marker, render a broken image area when source data exists, or lose the default still/backdrop/poster fallback order.
