3. Media Library / WD TV Live Architecture

The enhanced Media Library is a bridge between the website catalog and a local media device/storage target usable from home or trailer, reducing WAN traffic and Wi-Fi load when the media is local.

Network intent

LocationLocal networkIntent
Home192.168.1.xUse local WD TV Live/media device access.
Trailer192.168.2.xUse local/trailer-accessible path when the device is at trailer or reachable through trailer network.
FallbackUnknownShow path/status diagnostics and do not assume availability.

Required functions

  • Inventory local media folders and device-visible paths.
  • Map catalog item → expected file name → actual media file path.
  • Run media QA: ffprobe status, duration, video/audio stream, codec, container, extension match.
  • Repair/remux with stream copy when safe; quarantine/report if not safe.
  • Use local network paths to reduce trailer bandwidth/Wi-Fi load.

Workflow

catalog item
→ expected filename
→ local network profile
→ candidate media folders
→ file inventory
→ match confidence
→ ffprobe QA
→ optional ffmpeg remux
→ rename/move result
→ VLC/X-plore compatibility result
→ Media Library status

6. Codex / Documentation Direction

Build and maintain a UI Architecture Contract System.

Rules:
1. Every visible object gets a stable REF ID.
2. Every REF ID has one owner renderer and one CSS owner.
3. Dashboard/calendar/show/movie cards must use shared renderers.
4. Feedback must reference REF IDs.
5. Written requirements override mockup ambiguity.
6. User screenshots become validation cases.
7. New files are only created for materially new functionality.
8. Existing files are modified in place unless an owner does not exist.
9. Validation fails when duplicate renderer paths exist for the same object.
10. Media Library must support local network/device workflows for home and trailer use.
