Streaming Provider Registry

Version: 2026-08-11 streaming-provider-config-single-source

Added: Config-owned Streaming popup buttons, ordered fallback chain, inactive-provider retention, and metadata fields.

Updated: Runtime ownership moved from per-item watch.embed rendering and retired data/provider_registry.json references to web/config.json -> streaming.embed_providers[].

Origin: Runtime drift where the UI showed legacy providers despite newer research favouring TMDB-ID core/extras providers and config-only maintenance.

Owner: web/config.json owns provider data; web/js/app_runtime.js::collectConfiguredWatchSources owns rendering selection and URL generation.

Validation: scripts/validate_streaming_episode_cards.py, scripts/validate_runtime.ps1, and scripts/qa_browser_layout_check.mjs.

Source Of Truth

The only active source for Streaming popup provider buttons is web/config.json under streaming.embed_providers[]. Individual views must not hard-code provider buttons, data/provider_registry.json must not exist as active runtime input, and generated item payloads must not reduce or duplicate the active provider set.

Default Visible Providers

Default-visible providers are: VidCore, Vidfast, Vidlink, Vidsrc.pm, Vidsrc.to, Vidsrc.cc, 2embed.skin, nontongo.win, moviesapi.to, smashystream, autoembed.co, frembed, VSEmbed, VidEasy, SuperEmbed, and MultiEmbed.

Candidate And Blocked Providers

Inactive providers retained in config only: FlixHQ, SFlix, 2Embed CC, 2Embed Org, VidSrc (RU), VidSrc.net, VidSrc.me, Nunflix, vidsrc-embed.ru, Goojara, Cineb, and freeintertv.com.

Inactive providers must not become active until a real TMDB-compatible URL template is verified and their enabled, status, tier, and fallback-order placement are deliberately changed in web/config.json.

URL Template Rules

Templates use {tmdb_id}, {season}, and {episode} for TV episodes, and {tmdb_id} for movies. The runtime fills templates in collectConfiguredWatchSources. Missing IDs suppress the affected link rather than rendering a broken URL.

Validation Fail Rules

Validation fails if provider buttons are sourced from per-item watch.embed, data/provider_registry.json returns as an active input, default providers are missing, inactive providers render, provider buttons are hard-coded in Calendar or Dashboard views, generated runtime data duplicates streaming URLs, or the browser popup does not show the expected default provider set.
