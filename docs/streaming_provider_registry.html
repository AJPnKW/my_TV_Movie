Streaming Provider Registry

Version: 2026-05-20 streaming-provider-runtime-baseline

Added: Registry-driven Streaming popup buttons, candidate visibility flag, blocked-provider suppression.

Updated: Runtime ownership moved from per-item watch.embed rendering to web/config.json -> streaming.embed_providers[].

Origin: Runtime drift where the UI showed only VidSrc, VidEasy, FlixHQ, SFlix, and 2Embed CC despite a larger configured provider registry.

Owner: web/config.json owns provider data; web/js/app_runtime.js::collectConfiguredWatchSources owns rendering selection and URL generation.

Validation: scripts/validate_streaming_episode_cards.py, scripts/validate_runtime.ps1, and scripts/qa_browser_layout_check.mjs.

Source Of Truth

The only active source for Streaming popup provider buttons is web/config.json under streaming.embed_providers[]. Individual views must not hard-code provider buttons, and generated item payloads must not reduce the active provider set.

Status Rules

StatusRuntime behaviorMaintenance rule
okVisible by default.Use for verified TMDB-compatible templates.
warnVisible by default with icon-only degraded marking where needed.Use when service works but reliability is weaker.

blockedNever rendered.Use when no verified TMDB-compatible pattern exists or the provider is unsuitable.

Default Visible Providers

Default-visible providers are: VidSrc, VidEasy, SuperEmbed, MultiEmbed, SmashyStream, FlixHQ, SFlix, 2Embed CC, and 2Embed Org.

Candidate And Blocked Providers

Candidate providers currently hidden by default: VidSrc.me, VidSrc.to, VidLink, Nunflix, and vidsrc-embed.ru.

Blocked providers: Goojara, Cineb, and freeintertv.com. These must not become active until a real TMDB-compatible URL template is verified and their status is deliberately changed.

URL Template Rules

Templates use {tmdb_id}, {season}, and {episode} for TV episodes, and {tmdb_id} for movies. The runtime fills templates in collectConfiguredWatchSources. Missing IDs suppress the affected link rather than rendering a broken URL.

Validation Fail Rules

Validation fails if provider buttons are sourced from per-item watch.embed, default providers are missing, candidates render while the flag is false, blocked providers render, provider buttons are hard-coded in Calendar or Dashboard views, or the browser popup does not show the expected default provider set.
