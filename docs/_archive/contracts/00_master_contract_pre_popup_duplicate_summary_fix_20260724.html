Feature Parity Standard

  • Phone, tablet, desktop, Android TV, Google TV, Chromecast, and NVIDIA Shield expose the same functionality and content.
  • Responsive design may resize, wrap, collapse, or reposition controls; it must not hide, remove, replace, or fork Search, filters, sorting, cards, or actions.
  • Device type must not determine available controls, available filters, available content, Search availability, actions, result logic, or result counts.
  • Input-method adaptation for mouse, keyboard, touch, and D-pad/remote is allowed only when it preserves the same capability and state path.

Shared State and Component Standard

  • Shows and Movies have one canonical Search state: state.search.shows and state.search.movies.
  • Shows and Movies have one canonical release/status scope state: state.filters.shows.scope and state.filters.movies.scope.
  • The canonical scope controls are #filterShowsScope [data-scope] and #filterMoviesScope [data-scope]. They own active and aria-pressed through setSegActive.
  • There is one filter event path, one predicate path in renderShows/renderMovies, one result renderer, one active-state renderer, and one result-count calculation.
  • Device-specific scripts must not inject duplicate controls, maintain parallel filter state, apply separate card-hiding predicates, or update counts outside the canonical renderer.

Current Definitions

  • Current shows: first air date is not in the future; status is not Ended, Canceled, or Cancelled; and recent activity from last_air_date, latest_episode_to_air.air_date, or last_episode_to_air.air_date is inside web/config.json -> browse.current.show_activity_window_days = 183 by default. Status alone and next_episode_to_air alone do not make a show Current.
  • Current movies: release date is inside web/config.json -> browse.current.movie_release_window_days = 183 ending today by default; future releases are included only up to browse.current.movie_release_lookahead_days = 30 and only when existing availability metadata resolves to available.
  • The Current rules live only in web/js/app_runtime.js and read the configurable windows from web/config.json. They must not be duplicated in mobile scripts, CSS-hidden card filters, QA scripts without config reads, or page-shell inline code.

Cache and Release Standard

  • The central runtime release version is web/config.json _meta.version.
  • Active app shells must reference shared CSS and JavaScript with deterministic query parameters matching the release version, for example ./css/main_app.css?v=v1.5.4 and ./js/app_runtime.js?v=v1.5.4.
  • app_runtime.js must version its static module imports with the same release value so imported modules cannot remain stale under old unversioned URLs.
  • Generated runtime data is fetched with controlled revalidation/no-store through the existing loaders and must not be cache-busted with per-load random timestamps.
  • No service worker is registered by the active runtime. If a service worker is introduced later, its cache name must include the same release version and its update/removal path must be tested on normal navigation without hard refresh.
  • Deployment QA must load a previously deployed page, deploy or serve the new version, navigate normally without hard refresh, reload normally, navigate away and back, and prove the old UI does not return.

7. Trakt Sync Contract

device auth → pull → normalize → compare → local queue → push → confirmation pull → reconcile → report

8. Provider Health Registry

Provider links are treated as external health-checked targets. The app must not keep broken, unsafe, or redirect-abusive providers active.

Direct watch-source links must be filtered through data/provider_registry.json before rendering. Broken TLS, spam redirects, blank-tab launches, and inactive DNS are blocked states, not warnings.

FieldValue

Server-mode storage decision

  • PostgreSQL is the primary write store in server mode for media identity, watch status, watchlist, favourites, sync queue/history, provider registry, runtime config, audit log, and Media Library inventory.
  • JSON remains required for import, export, generated runtime output, recovery, and static GitHub Pages fallback.
  • data/inputs.json remains the canonical manual input source. data/data.json, data/catalog_index.json, data/calendar.json, and data/catalog_detail/*.json remain generated/runtime fallback artifacts.
  • Images, posters, stills, backdrops, provider logos, trailers, and media binaries are not stored in PostgreSQL by default. PostgreSQL stores metadata, identifiers, status fields, and paths to files/assets.
  • Secret values are not stored in schema seed data or API responses. Runtime config may store secret references only.

Database schema decision

  • The v1 schema includes media_items, shows, seasons, episodes, movies, watch_state, watchlist, favourites, sync_queue, sync_history, media_files, provider_registry, runtime_config, and audit_log.
  • watch_state stores only watched status/progress: unwatched, partial, and watched.
  • watchlist and favourites are independent tables. Their values cannot be inferred from watched status or from each other.
  • sync_queue preserves pending local actions. sync_history records pull, push, reconcile, local-only, failed, blocked, and partial outcomes.
  • audit_log is required for state writes, migration imports, sync conflict resolution, Media Library scan/remux decisions, and no-silent-loss evidence.

API decision

  • API base path is /api/v1.
  • In the X1 lab VM deployment path, Nginx owns the static entrypoint and future reverse proxy on 80/tcp with 443/tcp reserved for TLS. The local API upstream is 127.0.0.1:8000, matching the Lime Green reserved API port.
  • The server runtime app root is /opt/mytv_movie. PostgreSQL runs as the local VM service on 5432/tcp and must not be exposed beyond the VM/admin network.
  • Required endpoint groups are health, catalog, watch status, watchlist, favourites, Trakt pull/push/reconcile, providers, Media Library inventory/scan/QA/remux, runtime config, sync history/queue, and audit log.
  • State-changing API routes persist local PostgreSQL state first, write audit evidence, enqueue external sync work where applicable, and return local state immediately.
  • Trakt/commercial sync must not write by title-only matching. Stable IDs such as TMDB, IMDb, TVDB, Trakt ID, or Trakt slug are required for external writes.
  • partial watched status remains local unless a future explicit progress mapping is implemented. Favourites remain local-only by default unless an explicit external mapping is implemented.

Media Library decision

  • Media Library server workflow is scan -> identify -> filename match -> ffprobe QA -> classify -> safe remux if needed -> final validation -> report.
  • Home network profile is 192.168.1.x. Trailer network profile is 192.168.2.x. Manual override remains required when network detection is unavailable.
  • Inventory stores local device, device address where available, share/root/path, expected filename, actual filename, match state, ffprobe state, remux state, VLC state, X-plore state, and QA JSON.
  • Safe remux is stream copy by default. Transcoding requires a future explicit contract.
  • Bad/unrepairable files are quarantined and reported, never silently skipped.
