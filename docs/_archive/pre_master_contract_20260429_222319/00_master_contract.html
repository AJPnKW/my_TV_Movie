3.2 Filter Rail

  • Library/release filters use one common global left rail pattern.
  • Left rail remains left on desktop/tablet and stacks only on true mobile.
  • Hide/show control is on the rail edge, not inside filter content.
  • Use icon controls: show 👁, hide ✖ or 👁‍🗨, expand/collapse ▼ ▲ ▶ ◀ ➕ ➖ as appropriate.
  • Remove decorative/redundant text when it adds clutter: Browse, Library Filters where redundant, and Shared cards, shared actions, one left filter rail.

3.3 Media Cards

  • No availability badge overlays on poster/still artwork.
  • Show cards, movie cards, and episode cards each have one renderer family.
  • Reduce nested frames; keep frames only where they support card/date boundaries.

4. Calendar Contract

The calendar is spatial, not a generic responsive table. The week grid must preserve the Monday–Sunday mental model.

ElementContract
Week gridAlways seven columns: Monday, Tuesday, Wednesday, Thursday, Friday, Saturday, Sunday.
Reduced widthDo not collapse days into one vertical column. Use horizontal scrolling or a dedicated list mode.
Grid/list toggleGrid remains seven-column. Month List is a separate list mode, not an accidental responsive collapse.
Acceptance exampleIf partial browser width cannot fit seven columns, the page scrolls left/right while preserving all weekdays.

5. Watch State and Manage Watch State View

5.1 State Types

StateMeaningUI ControlNotes
watch_listUser intends to watch later.Compact two-state switch.Column header provides label; row control can be icon/switch only.
favouriteUser likes item / recommendation signal.Compact two-state switch.May remain local if no Trakt equivalent exists.
watched_statusUnwatched, partially watched, watched.Three-state segmented slider/switch.If Trakt only supports watched/unwatched, partial is local-only and must be mapped explicitly.

5.2 Manage Watch State Layout

  • Standalone page: web/manage_watch_state.html.
  • Must not be embedded in Config.
  • Primary nav icon required: ✅ Tracking.
  • Visual style should be compatible with watch_me.html, but the body is a lean data-control matrix, not a media card page.
  • Tree structure: Shows → Seasons → Episodes; Movies as single rows.
  • Columns: title/context, release status, identifiers, watch_list, watched_status, favourite, Trakt status, local/remote mismatch, queued update, validation issue.
  • Filters: type, release state, watch_list, watched_status, favourite, Trakt mismatch, missing ID, queued update, unreleased blocked.
  • Sorting: title, release date, status, Trakt mismatch, queued update.
  • Bulk actions allowed only where release-state constraints and hierarchy make them safe.

5.3 State Keys

<state_type>:movie:<tmdb_id>
<state_type>:show:<tmdb_id>
<state_type>:season:<show_id>:<season_number>
<state_type>:episode:<show_id>:<season_number>:<episode_number>

5.4 Release-State Constraints

  • Unreleased movie cannot be marked watched.
  • Unreleased episode cannot be marked watched.
  • Season watched status must derive from eligible released episodes.
  • Show rollup derives from seasons/episodes and cannot be guessed manually.
  • Partially watched is valid where some eligible child items are watched and others are not.

6. Trakt Integration Contract

Trakt integration is local-first, queue-based, explicit, and never blocks UI interaction.

Trakt pull → normalize → compare → local queue → push → pull confirmation → reconcile → report
WorkflowRequired Output
Pullwatched/history, watchlist, ratings/favourite-equivalent if available.
CompareLocal vs Trakt mismatch table.
PushQueued local changes sent to Trakt.
ReconcilePull after push and update local state.
Auth recoveryActionable error and token/device-auth recovery path.
  • Primary match key: tmdb_id. Never title-only matching.
  • Scripts to audit/integrate/archive: scripts/trakt_http.py, scripts/fetch_trakt.py, scripts/sync_trakt.py, scripts/trakt_device_auth.py, scripts/trakt_sync_watch_state.py, scripts/trakt_push_watch_queue.py, and scripts/run_pipeline_tmdb_trakt.py.
  • Discover uses Trakt-like logic to surface items not already present in local JSON sources.

8.3 Asset Workflow

  1. Download or preserve originals in assets/original_downloads/.
  2. Generate optimized runtime images into existing runtime asset folders.
  3. Keep JSON asset paths stable where possible.
  4. Do not leave oversized runtime images active after optimization.
  5. Validate dimensions, file size, missing files, broken references, and source/runtime mismatch.

Folder Properties alone are not sufficient proof. Validation must inspect each image's dimensions and file size.
