Watch State Keys Audit
Date: 2026-04-29

Canonical owner:
- web/js/watch_state_manager.js

Required watched_status keys:
- episode: watched_status:episode:<show_id>:<season>:<episode>
- movie: watched_status:movie:<tmdb_id>
- show: watched_status:show:<tmdb_id>

Related local-first state:
- watch_list uses the same item context with watch_list:<kind>:<id> and watch_list:episode:<show_id>:<season>:<episode>.
- favourite uses the same item context with favourite:<kind>:<id> and favourite:episode:<show_id>:<season>:<episode>.
- favourite remains local-only.

Findings:
- Generic data-id-only fallback was removed from watch_state_manager.js.
- Episode and season buttons without enough context now refuse to create a shared ambiguous key.
- Movie and show keys are explicitly keyed as movie/show before any compatibility fallback.
- Action buttons set data-watch-state-key after refresh so rendered DOM can be audited.

Validation status:
- Static source checks are enforced by scripts/validate_runtime.ps1.
- Browser/runtime smoke passed: visible action buttons on dashboard, calendar, shows, movies, and watch_me all had context-specific data-watch-state-key values.
