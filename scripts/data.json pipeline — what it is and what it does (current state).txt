## data.json pipeline — what it is and what it does (current state)

### Pipeline overview (end-to-end)

| Stage                | Where                                               | Primary inputs                                         | Primary outputs                        | Notes                                                                        |
| -------------------- | --------------------------------------------------- | ------------------------------------------------------ | -------------------------------------- | ---------------------------------------------------------------------------- |
| 0. Trigger           | GitHub Actions (`.github/workflows/build-data.yml`) | repo commit / manual run                               | workflow run                           | Single orchestration point                                                   |
| 1. Parse feed → JSON | `scripts/parse_txt_to_json.py`                      | your “feed” TXT(s)                                     | intermediate JSON (used by TMDB fetch) | Produces the show/movie ID lists the pipeline works from                     |
| 2. TMDB fetch/build  | `scripts/fetch_tmdb.py`                             | intermediate JSON + `web/config.json` + TMDB API creds | `data/data.json`                       | Creates baseline structure and (intended) streaming URLs + image-local paths |
| 3. Trakt enrichment  | `scripts/fetch_trakt.py`                            | `data/data.json` + Trakt client id                     | updated `data/data.json`               | Adds `trakt_id` via public search                                            |
| 4. Trakt sync        | `scripts/sync_trakt.py`                             | `data/data.json`                                       | side-effects + updates                 | Runs after enrichment                                                        |
| 5. Commit back       | workflow git steps                                  | changed files                                          | push to repo                           | Data file becomes “source of truth” for UI                                   |

(Workflow evidence)

* Runs parse → fetch_tmdb → fetch_trakt → sync_trakt → commit/push.

## Known failure points (current)

| Area                 | Current behavior                                                                                        | Impact in UI                                                 |
| -------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Streaming link bases | `fetch_tmdb.py` expects `config.json.streaming.*` but your file uses `config.json.streaming_services.*` | base URL becomes `""`, so links become just `"1319951"` etc. |
| Image cache pathing  | `config.json` uses `/image/...` but `config.js` treats `image/` as deprecated and expects `assets/...`  | local images don’t resolve / inconsistent paths              |
| Episode/season build | Current builder outputs `seasons: []` and notes a “deep build later” that isn’t present in the workflow | UI lacks season/episode navigation + episode-level links     |
| Schema breadth       | Builder is minimal (no genres, overview, ratings, external IDs, etc.)                                   | UI can’t render “rich cards” without additional fields       |

(Streaming key mismatch evidence)

* `web/config.json` has `streaming_services.*`

* `fetch_tmdb.py` reads `streaming.*`

* Output symptom: links are just the id string
